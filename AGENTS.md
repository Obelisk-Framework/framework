# AGENTS.md - Obelisk Framework Development Guide

## Build & Development Commands

### Web (Vue 3)
```bash
cd web
npm install          # Install dependencies
npm run dev          # Start dev server with HMR
npm run build        # Production build to ../core/html
```

### CLI & Root
```bash
npm install          # Install Node dependencies
npm run make:module  # Generate module boilerplate
npm run make:plugin  # Generate plugin boilerplate
npm run make:model   # Generate ORM model
npm run make:migration  # Generate database migration
npm run make:seeder  # Generate database seeder
npm run make:action  # Generate action handler
npm run make:interaction  # Generate interaction
npm run make:policy  # Generate authorization policy
```

### Database & Server
```bash
# Start MariaDB (requires Docker)
docker-compose up -d

# View MariaDB logs
docker-compose logs mariadb

# Stop MariaDB
docker-compose down
```

### Tests

```bash
npm test             # runs the Lua unit tests (requires lua5.4)
```

The pure ORM logic (query building, escaping, schema DDL) has unit tests under
`tests/` runnable without a FiveM server — see `tests/README.md`. Runtime code
(net events, NUI, natives, real DB I/O) is still tested manually on a server.

## MySQL Setup

**Obelisk requires a MySQL connector resource.** See SETUP_MYSQL.md for detailed instructions.

Required: One of these resources
- ghmattimysql (recommended)
- oxmysql
- mysql-async

Server.cfg example:
```cfg
ensure ghmattimysql
ensure obelisk
set mysql_connection_string "mysql://obelisk:obelisk_password@mariadb:3306/fivem"
```

## Code Style Guidelines

### Lua (Server/Client)
- **Service Pattern**: Stateless services with static methods (e.g., `ActionService.register()`)
- **ORM Models**: Extend `BaseModel` with Active Record pattern (hasOne, hasMany, belongsTo, belongsToMany)
- **Naming**: CamelCase for functions, snake_case for table names and action IDs
- **Imports**: Use `return ModuleName` at end of files; require() from bootstrap files
- **Type Hints**: Use LuaLS annotations (`@param`, `@return`, `@table`)
- **Async**: Prefer Sync versions for simplicity (`findSync()`, `getSync()`)
- **Error Handling**: Use `pcall()` in service handlers; print to console for logging
- **Hooks**: Use `Hooks.runHook()` for extensibility points before/after operations

### Vue 3 (Web/Components)
- **Setup API**: Use `<script setup>` composition API only
- **Imports**: Alias `@` for `/src`, use scoped styles always
- **Naming**: PascalCase for components (e.g., `Notifications.vue`)
- **State**: Use `ref()` and `computed()` for reactivity
- **Event Handling**: camelCase event names, use `@event` in templates
- **Styling**: TailwindCSS utility classes; scoped `<style scoped>` blocks
- **NUI**: Use `useNui()` composable for Lua ↔ Vue communication via fetch callbacks

### JavaScript/Node (CLI)
- **Generators**: Use commander.js for CLI structure, inquirer.js for prompts
- **File Operations**: Use fs-extra for safe file handling
- **Logging**: Use chalk for colorized console output
- **Module Structure**: Export single responsibility generators as commands

## Project Structure
- `core/server/` - Backend logic, ORM, services, migrations
- `core/client/` - Client services, actions, keybinds
- `web/` - Vue 3 frontend built via Vite
- `core/html/` - Built Vue output (auto-generated by `npm run build`)
- `modules/` - Core feature modules (Items, Vehicles, etc.)
- `plugins/` - Optional feature plugins with separate fxmanifest.lua
- `cli/` - Node.js code generators

## Common Patterns

**Register Action**: `ActionService.register('action_id', handler, options)`
**Query Models**: `Model:newQuery():where(...):first(callback)` or `:firstSync()`
**Migrations**: Use `Schema.create/drop` with fluent table methods
**Policies**: Register with `PolicyService.register()`, attach to actions/interactions
**Notifications**: `NotificationService.success(source, title, description, duration)`
